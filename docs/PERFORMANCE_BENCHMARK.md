# Qwen3·LangChain·RAG 성능 비교

## 1. 측정 목적

현재 노래방 AI Agent에서 사용하는 모델과 처리 구조를 동일 조건으로 비교했다.

1. Qwen3 1.7B와 Qwen3 8B의 기기 제어 정확도·응답시간 비교
2. Raw Ollama 출력과 LangChain 구조화 출력 + Pydantic 검증 비교
3. 일반 Qwen 답변과 RAG 문서 기반 답변 비교

이 문서의 수치는 추정값이 아니라 로컬 환경에서 실제 모델을 호출한 결과다.

---

## 2. 측정 환경

- GPU: NVIDIA GeForce RTX 4070 Laptop GPU, VRAM 8,188MB
- Ollama: 0.34.2
- 생성 모델
  - `qwen3:1.7b`, Q4_K_M
  - `qwen3:8b`, Q4_K_M
- 임베딩 모델: `bge-m3`
- 벡터 저장소: Chroma
- temperature: 0
- seed: 42
- 컨텍스트 길이: 4,096
- 모델·파이프라인별 첫 호출은 워밍업으로 실행하고 측정에서 제외
- 각 평가 항목은 1회 측정
- 전체 실행시간: 약 23분 5초

응답시간은 요청 직전부터 전체 응답이 끝날 때까지 `time.perf_counter()`로 측정했다. RAG 인덱스 준비시간은 질문별 응답시간에서 제외하고 별도로 기록했다.

---

## 3. Qwen3 1.7B와 8B 기기 제어 비교

LangChain 구조화 출력과 Pydantic 검증을 적용한 실제 기기 제어 경로를 비교했다.

| 모델 | 명령 정확도 | JSON 성공률 | 스키마 성공률 | 평균 | 중앙값 | P95 |
|---|---:|---:|---:|---:|---:|---:|
| Qwen3 1.7B | 100.0% (9/9) | 100.0% | 100.0% | 4.66초 | 4.70초 | 5.36초 |
| Qwen3 8B | 100.0% (9/9) | 100.0% | 100.0% | 16.21초 | 15.18초 | 24.01초 |

### 결과

- 두 모델 모두 9개 명령을 정확하게 처리했다.
- Qwen3 1.7B의 평균 응답시간은 Qwen3 8B보다 **71.2% 짧았다.**
- 같은 표현으로는 Qwen3 1.7B가 Qwen3 8B보다 평균 기준 **약 3.48배 빨랐다.**
- 현재 명령 범위에서는 8B의 추가 모델 크기가 정확도 향상으로 이어지지 않았다.
- 따라서 실제 기기 제어에는 정확도를 유지하면서 응답시간이 짧은 Qwen3 1.7B를 선택했다.

평가 명령에는 음정 증감과 범위 초과, 일반·우선 예약, 예약 취소, 예약곡 시작, 보컬 제거 해제, 지원하지 않는 조명 요청이 포함됐다. 예상 필드 외의 상태가 바뀌면 오답으로 처리했다.

## 4. LangChain 구조화 출력 적용 전후

여기서 `Raw`는 같은 시스템 프롬프트와 현재 상태를 Ollama 자유 출력으로 요청한 방식이다. `Structured`는 LangChain `with_structured_output(KaraokeMachine)`으로 출력 구조를 제한하고 Pydantic으로 검증한 현재 처리 방식이다.

### Qwen3 1.7B

| 방식 | JSON 성공률 | 스키마 성공률 | 명령 정확도 | 평균 응답시간 |
|---|---:|---:|---:|---:|
| Raw Ollama | 100.0% (9/9) | 88.9% (8/9) | 88.9% (8/9) | 4.40초 |
| LangChain + Pydantic | 100.0% (9/9) | 100.0% (9/9) | 100.0% (9/9) | 4.66초 |

- 스키마 성공률: **88.9% → 100.0%, 11.1%p 향상**
- 명령 정확도: **88.9% → 100.0%, 11.1%p 향상**
- 평균 지연 증가: **0.26초, 약 5.8%**
- Raw 실패 원인: 예약 결과에서 전체 상태가 아니라 변경된 `queue`만 반환해 필수 필드 검증에 실패

### Qwen3 8B

| 방식 | JSON 성공률 | 스키마 성공률 | 명령 정확도 | 평균 응답시간 |
|---|---:|---:|---:|---:|
| Raw Ollama | 100.0% (9/9) | 66.7% (6/9) | 66.7% (6/9) | 16.51초 |
| LangChain + Pydantic | 100.0% (9/9) | 100.0% (9/9) | 100.0% (9/9) | 16.21초 |

- 스키마 성공률: **66.7% → 100.0%, 33.3%p 향상**
- 명령 정확도: **66.7% → 100.0%, 33.3%p 향상**
- Raw 실패 3건은 일부 필수 필드를 생략한 부분 JSON 출력 때문이었다.
- 구조화 방식이 평균 0.30초 짧게 측정됐지만 표본이 작으므로 속도 향상으로 해석하지 않는다.

### 전체 결과

두 모델을 합치면 Raw 방식의 스키마·명령 성공은 **77.8% (14/18)**, 구조화 방식은 **100.0% (18/18)**였다. 즉, 구조화 출력과 Pydantic 검증을 적용하면서 성공률이 **22.2%p 향상**됐다.

이 결과는 LangChain이 모델의 추론 능력 자체를 높였다는 뜻이 아니다. 출력 스키마 제공, 구조화 출력 강제, Pydantic 검증을 포함한 전체 처리 방식이 애플리케이션에서 사용할 수 있는 완전한 상태 JSON의 비율을 높였다는 의미다.

## 5. 일반 Qwen 답변과 RAG 비교

프로젝트 문서에만 있는 7개 질문과 문서 범위 밖 질문 2개를 사용했다.

| 모델·방식 | 문서 질문 정확도 | 검색 성공률 | 정답 출처 일치율 | 범위 밖 거절률 | 중앙 응답시간 |
|---|---:|---:|---:|---:|---:|
| Qwen3 1.7B 일반 답변 | 0.0% (0/7) | 해당 없음 | 해당 없음 | 해당 없음 | 3.58초 |
| Qwen3 1.7B RAG | 71.4% (5/7) | 71.4% (5/7) | 71.4% (5/7) | 100.0% (2/2) | 2.16초 |
| Qwen3 8B 일반 답변 | 0.0% (0/7) | 해당 없음 | 해당 없음 | 해당 없음 | 8.97초 |
| Qwen3 8B RAG | 71.4% (5/7) | 71.4% (5/7) | 71.4% (5/7) | 100.0% (2/2) | 4.23초 |

### 결과

- 일반 Qwen은 프로젝트 전용 설정을 전달받지 않아 7개 질문 모두 정답 조건을 충족하지 못했다.
- RAG 적용 후 두 모델 모두 **5/7, 71.4%**의 문서 질문 정확도를 기록했다.
- 관련 문서를 찾은 5건은 정답 출처 파일도 모두 일치했다.
- 프랑스 인구와 김치찌개 조리법처럼 자료 범위 밖인 질문은 두 모델 모두 **2/2 정확히 거절**했다.
- 실패한 2건은 생성 모델 오류가 아니라 검색 점수가 현재 임계값을 넘지 못해 답변 단계로 전달되지 않은 사례였다.
  - 지원하는 공간 음향 유형
  - 음성 녹음 파일의 최대 크기
- 따라서 다음 검색 품질 개선 대상은 임베딩 검색 임계값과 질문·문서 표현 차이다.

Qwen3 1.7B 일반 답변 중 범위 밖 레시피 질문 한 건이 566.36초 걸린 이상치가 있었다. 이 때문에 평균은 66.28초로 크게 왜곡됐다. 따라서 이 비교에서는 중앙값을 대표값으로 함께 제시한다. 이상치를 삭제하거나 다른 값으로 대체하지 않고 원본 JSON에 그대로 보존했다.

---

## 6. 결론

1. **모델 선택:** 구조화된 기기 제어 정확도는 1.7B와 8B 모두 100%였지만, 1.7B가 평균 약 3.48배 빨랐다.
2. **LangChain 구조화 출력:** 두 모델 합산 성공률이 77.8%에서 100.0%로 22.2%p 향상됐다.
3. **RAG:** 프로젝트 전용 질문 정확도가 일반 Qwen의 0%에서 71.4%로 높아졌고, 범위 밖 질문은 100% 거절했다.
4. **남은 개선점:** 현재 RAG 검색이 7개 문서 질문 중 2개를 놓쳤으므로 검색 임계값과 검색 데이터 표현을 조정하고 별도 평가셋으로 재검증해야 한다.
