# Qwen3·LangChain·RAG 성능 비교

## 1. 결론 요약

동일한 로컬 환경에서 각 항목을 3회 반복한 결과다.

- 실제 기기 제어 경로인 `LangChain with_structured_output + Pydantic`에서는 Qwen3 1.7B와 8B가 모두 **명령 정확도 100%(27/27)**를 기록했다.
- 같은 구조화 경로에서 Qwen3 1.7B의 평균 응답시간은 **4.83초**, 8B는 **13.13초**였다. 1.7B가 약 **2.72배 빠르고**, 평균 지연이 **63.2% 짧았다**.
- Raw Ollama 대비 구조화 출력 적용 후 1.7B의 명령 정확도는 **81.5% → 100%(+18.5%p)**, 8B는 **59.3% → 100%(+40.7%p)**로 높아졌다. 평균 지연 증가는 각각 **6.2%, 8.8%**였다.
- RAG의 답변 정확도는 Qwen3 1.7B **61.9%(13/21)**, 8B **71.4%(15/21)**였다. 검색 성공률과 출처 일치율은 두 모델 모두 **71.4%(15/21)**, 범위 밖 질문 거절률은 **100%(6/6)**였다.
- 전체 문서를 한 번에 제공한 기준선은 두 모델 모두 **85.7%(18/21)**로 RAG보다 정확했지만, RAG가 평균 응답시간은 1.7B에서 **51.4%**, 8B에서 **48.1%** 짧았다. 따라서 현재 RAG는 정확도 향상이 아니라 **입력 문맥 축소와 응답시간 단축의 대가로 검색 누락이 발생하는 구조**로 해석해야 한다.

## 2. 측정 조건

- 모델: `qwen3:1.7b`, `qwen3:8b`
- 양자화: 두 모델 모두 `Q4_K_M`
- 실행 환경: Windows 10, Ollama 로컬 실행
- 생성 설정: `temperature=0`, `seed=42`
- 반복 횟수: 각 사례 3회
- 기기 제어 데이터: 9개 명령 × 3회 × 2모델 × 2방식 = 108건
- 문서 질의 데이터: 9개 질문 × 3회 × 2모델 × 3방식 = 162건
- 총 최종 기록: **270건**
- QA 출력 상한: 모든 모델·방식에 `num_predict=512` 동일 적용
- 전체 문서 기준선의 컨텍스트 창: 8,192
- 워밍업과 RAG 인덱스 구성 시간은 응답시간 집계에서 제외
- 응답시간은 클라이언트의 wall-clock 시간이며 평균·중앙값·모표준편차·nearest-rank P95를 기록

정확도는 미리 정의한 필드·키워드·출처 파일명으로 판정했다. 키워드 판정은 의미 평가를 완전히 대신하지 못한다.

## 3. Qwen3 1.7B와 8B의 기기 제어 성능

실제 서비스와 같은 LangChain 구조화 출력 + Pydantic 경로를 기준으로 비교했다.

| 모델 | 명령 정확도 | 평균 | 중앙값 | 표준편차 | P95 |
|---|---:|---:|---:|---:|---:|
| Qwen3 1.7B | **100% (27/27)** | **4.83초** | 4.64초 | 0.95초 | 7.27초 |
| Qwen3 8B | **100% (27/27)** | 13.13초 | 12.55초 | 2.86초 | 19.19초 |

두 모델의 정확도가 같았으므로 지연시간이 짧은 Qwen3 1.7B를 기기 제어 모델로 선택할 근거가 확인됐다. 다만 9개 명령으로 구성한 프로젝트 내부 평가이므로 일반적인 모델 우열로 확대해서는 안 된다.

## 4. Raw Ollama와 LangChain 구조화 출력 비교

비교 대상은 LangChain 라이브러리 단독 효과가 아니라 다음 전체 처리 묶음이다.

```text
Raw Ollama 자유 형식 JSON
vs
LangChain with_structured_output + Pydantic 전체 상태 스키마 검증
```

### Qwen3 1.7B

| 방식 | JSON 형식 | 스키마 검증 | 명령 정확도 | 평균 |
|---|---:|---:|---:|---:|
| Raw Ollama | 100% | 81.5% | 81.5% (22/27) | 4.55초 |
| 구조화 출력 + Pydantic | **100%** | **100%** | **100% (27/27)** | 4.83초 |

- 명령 정확도: **+18.5%p**
- 평균 지연: **+0.28초, +6.2%**

### Qwen3 8B

| 방식 | JSON 형식 | 스키마 검증 | 명령 정확도 | 평균 |
|---|---:|---:|---:|---:|
| Raw Ollama | 100% | 59.3% | 59.3% (16/27) | 12.06초 |
| 구조화 출력 + Pydantic | **100%** | **100%** | **100% (27/27)** | 13.13초 |

- 명령 정확도: **+40.7%p**
- 평균 지연: **+1.06초, +8.8%**

두 모델 모두 10% 미만의 평균 지연 증가로 명령 정확도가 100%까지 향상돼, LangChain 구조화 출력과 Pydantic 검증이 기기 제어 안정성에 유의미한 효과를 보였다.

## 5. RAG 비교 기준

세 조건을 구분했다.

1. **문서 없는 일반 Qwen(direct)**: 프로젝트 지식이 없을 때의 외부 지식 기준선
2. **전체 문서 제공(full_context)**: 모든 프로젝트 문서를 같은 grounding 정책으로 제공
3. **RAG**: bge-m3와 Chroma가 검색한 조각만 같은 grounding 정책으로 제공

일반 Qwen과 RAG의 직접 비교는 문서 유무가 달라 RAG 검색 방식의 공정한 성능 비교가 아니다. RAG 자체의 검색 효과와 손실은 **전체 문서 제공과 RAG**를 중심으로 판단했다.

### 답변 성능

정답 가능한 7개 질문을 모델별 3회씩 측정했다.

| 모델 | 방식 | 답변 정확도 | 검색 성공률 | 출처 일치율 | 범위 밖 거절률 |
|---|---|---:|---:|---:|---:|
| 1.7B | 문서 없음 | 14.3% (3/21) | 해당 없음 | 해당 없음 | 해당 없음 |
| 1.7B | 전체 문서 | **85.7% (18/21)** | 해당 없음 | 해당 없음 | **100% (6/6)** |
| 1.7B | RAG | 61.9% (13/21) | 71.4% (15/21) | 71.4% (15/21) | **100% (6/6)** |
| 8B | 문서 없음 | 0% (0/21) | 해당 없음 | 해당 없음 | 해당 없음 |
| 8B | 전체 문서 | **85.7% (18/21)** | 해당 없음 | 해당 없음 | **100% (6/6)** |
| 8B | RAG | 71.4% (15/21) | 71.4% (15/21) | 71.4% (15/21) | **100% (6/6)** |

문서 없는 일반 Qwen의 우연한 키워드 일치는 프로젝트 근거를 사용한 답변이 아니므로 RAG 품질 근거로 사용하지 않는다.

### 응답시간

| 모델 | 방식 | 평균 | 중앙값 | 표준편차 | P95 |
|---|---|---:|---:|---:|---:|
| 1.7B | 문서 없음 | 4.03초 | 3.79초 | 1.22초 | 5.64초 |
| 1.7B | 전체 문서 | 2.61초 | 2.52초 | 0.78초 | 4.15초 |
| 1.7B | RAG | **1.27초** | 1.57초 | 1.16초 | 2.98초 |
| 8B | 문서 없음 | 10.91초 | 10.26초 | 3.63초 | 17.15초 |
| 8B | 전체 문서 | 7.93초 | 8.19초 | 1.86초 | 11.11초 |
| 8B | RAG | **4.12초** | 5.29초 | 3.76초 | 8.98초 |

RAG는 관련 조각을 찾지 못하면 생성 호출 없이 정책 문장을 반환하므로 평균 시간이 짧아지는 효과도 포함한다.

### 실패 원인

- `공간 음향 유형`: 두 모델 모두 검색 임계값을 통과하지 못함
- `음성 파일 최대 크기`: 두 모델 모두 검색 임계값을 통과하지 못함
- `API DISCONNECTED 확인 주소`: 검색과 출처는 3/3 성공했지만 1.7B 답변의 키워드 판정은 1/3 성공
- 전체 문서 기준선도 모델별 한 질문에서 3회 실패해 85.7%를 기록함

현재 병목은 모델 크기만이 아니라 검색 임계값·문서 분할·질의 표현과 생성 답변의 안정성이다.

## 6. 장기 생성 재측정

최초 QA 측정에서 아래 3건이 120초를 넘었다.

| 모델 | 방식 | 질문 | 회차 | 최초 시간 |
|---|---|---|---:|---:|
| Qwen3 1.7B | 문서 없는 일반 Qwen | 김치찌개 4인분 레시피 | 1 | 627.99초 |
| Qwen3 1.7B | 문서 없는 일반 Qwen | 김치찌개 4인분 레시피 | 2 | 630.94초 |
| Qwen3 1.7B | 문서 없는 일반 Qwen | 김치찌개 4인분 레시피 | 3 | 682.69초 |

세 출력 모두 같은 문구를 반복하며 32,528자까지 생성한 퇴행 사례였다. HTTP timeout은 토큰이 계속 전송되면 전체 경과시간 제한으로 작동하지 않았다.

다음과 같이 처리했다.

1. 기존 QA 162건 전체와 장기 생성 답변 본문을 최종 결과에서 삭제
2. 두 모델의 일반 Qwen·전체 문서·RAG에 `num_predict=512`를 동일 적용
3. QA 162건 전체를 3회 조건으로 다시 측정
4. 최종 결과에 새 QA 기록만 병합

재측정 결과 호출 실패와 120초 초과는 모두 **0건**이었고, QA의 최장 응답은 **17.29초**였다. 최종 JSON에는 삭제한 답변 본문이 없으며 모델·방식·질문·회차·기존 시간만 재시도 이력으로 남겼다.

## 7. 해석 한계

- 9개 명령과 9개 질문으로 구성한 프로젝트 내부 평가다.
- 정확도는 사람이 정의한 필드와 키워드를 기준으로 계산했다.
- 전체 문서 방식은 모든 자료가 작은 컨텍스트에 들어가는 현재 프로젝트에서는 강한 기준선이지만, 문서가 커지면 비용과 컨텍스트 제한이 증가한다.
- RAG의 낮은 검색 성공률을 생성 모델 성능 저하로 해석하면 안 된다.
- Raw와 구조화 출력 비교는 프롬프트·출력 제약·검증을 포함한 시스템 비교다.
- 로컬 하드웨어·Ollama 버전·백그라운드 부하에 따라 절대 응답시간은 달라질 수 있다.
