# 문제 해결 안내

이 문서는 Karaoke AI Agent 데모에서 발생할 수 있는 연결·음성 인식·모델·명령 처리 문제를 확인하는 순서를 설명한다.

## API가 DISCONNECTED로 표시될 때

상단 상태가 `API: DISCONNECTED`라면 프론트엔드가 `http://127.0.0.1:8000/docs`에 접근하지 못한 상태다.

1. 백엔드를 `python -m uvicorn backend.main:app --reload`로 실행했는지 확인한다.
2. 브라우저에서 `http://127.0.0.1:8000/docs`가 열리는지 확인한다.
3. 프론트엔드의 `API_BASE`가 실제 백엔드 주소와 같은지 확인한다.
4. 다른 프로그램이 8000 포트를 사용 중인지 확인한다.
5. 백엔드 로그에 Python 패키지 또는 모델 초기화 오류가 있는지 확인한다.

Ping 버튼은 API 연결 여부를 다시 확인한다. 연결이 복구되면 `API: CONNECTED`로 바뀐다.

## Ollama 또는 Qwen 모델 오류

텍스트 명령과 RAG 답변 생성에는 Ollama가 필요하다. Ollama 서버가 실행 중이어야 하고 `qwen3:1.7b` 모델이 설치되어 있어야 한다.

확인 명령:

```bash
ollama list
ollama pull qwen3:1.7b
```

연결 오류가 나면 Ollama 애플리케이션 또는 서버를 먼저 실행한다. 모델명이 환경설정과 다른 경우 `RAG_CHAT_MODEL` 및 기존 `ChatOllama` 설정을 확인한다.

## RAG 임베딩 모델 오류

문서 검색에는 기본적으로 `nomic-embed-text` 임베딩 모델을 사용한다. 첫 질문에서 임베딩 모델을 찾지 못했다는 오류가 발생하면 다음을 실행한다.

```bash
ollama pull nomic-embed-text
ollama list
```

지식 문서가 비어 있거나 `backend/knowledge` 경로를 찾지 못한 경우에도 RAG는 준비되지 않는다. Markdown 문서가 존재하는지 확인한다.

## 마이크 권한이 필요하다고 표시될 때

브라우저 주소창의 마이크 권한을 허용한다. 운영체제 개인정보 설정에서도 Chrome 또는 사용하는 브라우저의 마이크 접근이 허용되어야 한다. 다른 화상회의 프로그램이 마이크를 독점하고 있다면 종료한 뒤 다시 시도한다.

마이크 권한 문제는 기기의 MIC 음량값을 높이는 것으로 해결되지 않는다. 권한과 입력 장치 연결을 먼저 확인한다.

## 음성 인식 결과가 비어 있을 때

`음성 인식 결과가 비어있어요` 또는 `음성 인식 실패`가 표시되면 다음을 확인한다.

1. 녹음 시작 후 실제로 말했는지 확인한다.
2. 브라우저와 운영체제에서 올바른 마이크가 선택됐는지 확인한다.
3. 너무 짧게 말하거나 주변 소음만 녹음되지 않았는지 확인한다.
4. faster-whisper 모델이 정상적으로 내려받아졌는지 확인한다.
5. webm 처리를 위한 ffmpeg 환경에 문제가 없는지 백엔드 로그를 확인한다.
6. `WHISPER_DEVICE`와 `WHISPER_COMPUTE` 설정이 현재 CPU 또는 GPU 환경에 맞는지 확인한다.

기본 설정은 `WHISPER_MODEL=small`, `WHISPER_DEVICE=cpu`, `WHISPER_COMPUTE=int8`이다.

## 명령을 말했는데 상태가 바뀌지 않을 때

먼저 화면의 reason과 `changed` 값을 확인한다. `changed=false`라면 다음 가능성이 있다.

- 이미 같은 상태여서 변경할 값이 없음
- 요청이 모호함
- 지원하지 않는 기능임
- 숫자가 허용 범위를 벗어남
- 예약 취소 대상이 목록에 없음
- 음성 인식 문장이 의도와 다르게 변환됨

인식된 문장은 브라우저 개발자 콘솔의 `STT` 로그와 명령 입력창에서 확인할 수 있다. 명령을 더 짧고 구체적으로 다시 입력해 본다. 예: `키 10 올려줘` 대신 허용 범위 안에서 `키 한 칸 올려줘`를 사용한다.

## RAG가 관련 없는 답을 할 때

RAG 답변 아래의 참조 문서와 발췌문을 확인한다. 질문과 맞지 않는 문서가 검색됐다면 질문에 기능 이름을 포함해 구체적으로 작성한다. 예: `안 돼`보다 `마이크 음성 인식 결과가 비어 있어`가 좋다.

문서에 근거가 없으면 RAG는 `제공된 문서에서 확인할 수 없습니다.`라고 답해야 한다. 날씨·뉴스·결제처럼 문서 범위 밖 질문에 일반 지식으로 답하면 정상 동작이 아니다.

## 페이지 레이아웃이 깨질 때

브라우저 확대 비율을 100%로 맞추고 새로고침한다. 데스크톱 넓은 화면에서는 기기 오른쪽에 RAG 패널이 표시되고 좁은 화면에서는 기기 아래로 이동한다. 오래된 CSS가 캐시된 경우 강력 새로고침을 사용한다.

## 초기화와 상태 복구

상단 `Reset` 버튼은 프론트엔드의 기기 상태를 초기값으로 되돌린다. 예약 목록과 재생 상태도 초기화된다. RAG 검색 인덱스나 지식 문서를 삭제하는 기능은 아니다.
